# cal-todo 사용자 시나리오

> 기준 문서: [도메인 정의서](1-domain-definition.md), [PRD](2-PRD.md). FR/BR ID는 두 문서와 동일하며 상세 규칙·정의는 해당 문서를 따른다. 미정이던 항목은 [개발 계획 §5](8-plan.md)에서 확정되었다 (§6 참조).

## 1. 개요
- 대상 사용자: 학생 및 20~50대 직장인 (PRD §2). 상세 페르소나는 작성하지 않는다.
- 범위: FR-01 ~ FR-08 전체. 화면 다국어(한국어·영어)·다크/라이트 모드 전환(PRD §3)은 UI 범위로 별도 시나리오를 두지 않는다. 정상 흐름(S)과 예외/경계 흐름(E)으로 구분한다.
- 상태 판단의 '오늘'은 KST 기준이다 (BR-08).

## 4. 정상 시나리오

### S-01 회원가입
- 관련 ID: FR-01, BR-01, BR-07
- 사전 조건: 사용자가 미가입 상태이며 사용하지 않은 이메일을 가진다.
- 행동 흐름:
  1. 회원가입 화면에서 이메일, 비밀번호, 이름을 입력한다.
  2. 가입을 요청한다.
- 기대 결과: 계정이 생성된다. 앱을 사용하려면 이어서 로그인해야 한다 (BR-01).

### S-02 로그인
- 관련 ID: FR-01, BR-01
- 사전 조건: 가입된 계정이 있다.
- 행동 흐름:
  1. 로그인 화면에서 이메일과 비밀번호를 입력한다.
  2. 로그인을 요청한다.
- 기대 결과: 서버가 Access Token과 Refresh Token을 발급하고 사용자는 앱을 사용할 수 있다. Access Token 만료 시 Refresh Token으로 새 Access Token을 발급받는다 (PRD §6). 만료 시간은 Access Token 15분, Refresh Token 7일이며 두 토큰 모두 localStorage에 저장한다.

### S-03 내 정보 수정
- 관련 ID: FR-02, BR-01
- 사전 조건: 로그인 상태.
- 행동 흐름:
  1. 내 정보 화면을 연다.
  2. 이름을 수정하고 저장한다.
- 기대 결과: 수정 내용이 저장되어 반영된다. 수정 가능한 항목은 이름만이다 (이메일·비밀번호 변경 불가).

### S-04 할일 등록 (기본값 사용)
- 관련 ID: FR-03, BR-01, BR-03, BR-05, BR-06
- 사전 조건: 로그인 상태.
- 행동 흐름:
  1. 할일 등록 화면을 연다. 시작일자는 일주일 후 날짜, 종료일자는 시작일자와 동일하게 채워져 있다.
  2. 제목을 입력한다.
  3. 필요 시 캘린더에서 시작일자·종료일자를 선택하고 카테고리를 지정한다. 카테고리는 지정하지 않을 수 있다.
  4. 저장한다.
- 기대 결과: 할일이 본인 소유로 저장된다. 카테고리 미지정 시 '기본'으로 적용된다. 완료 여부는 false다.

### S-05 할일 수정
- 관련 ID: FR-04, BR-02, BR-04, BR-06, BR-12
- 사전 조건: 로그인 상태이며 본인 할일이 존재한다.
- 행동 흐름:
  1. 할일을 선택해 편집 화면을 연다.
  2. 제목, 카테고리, 시작·종료일자(캘린더 선택) 등을 수정한다.
  3. 저장한다.
- 기대 결과: 변경 내용이 저장된다. 날짜 검증은 등록과 동일하다. 완료 처리는 편집 화면이 아니라 목록의 체크박스 토글로 하며 되돌릴 수 있다 (BR-12).

### S-06 할일 삭제
- 관련 ID: FR-05, BR-02
- 사전 조건: 로그인 상태이며 본인 할일이 존재한다.
- 행동 흐름:
  1. 삭제할 할일에서 삭제를 요청한다.
  2. 확인창(1회)에서 확인한다. 취소하면 삭제되지 않는다.
- 기대 결과: 해당 할일이 삭제되고 조회 화면에서 사라진다.

### S-07 목록·캘린더 조회
- 관련 ID: FR-06, BR-02
- 사전 조건: 로그인 상태이며 본인 할일이 여러 건 있다.
- 행동 흐름:
  1. 할일 조회 화면에서 목록 탭을 확인한다.
  2. 캘린더 탭으로 전환하여 월별 캘린더에서 할일을 확인한다.
  3. 캘린더에서 날짜 셀을 클릭한다.
- 기대 결과: 두 탭 모두 본인 할일만 표시된다. 캘린더에는 필터가 적용되지 않는다. 여러 날에 걸친 할일은 시작일자~종료일자의 각 날짜 셀에 표시되며, 셀에 3건을 넘으면 '+N'으로 표시한다. 날짜 셀을 클릭하면 그날의 할일(상태·제목·기간)이 팝업으로 표시되고, 할일이 없으면 "이 날짜에 일정이 없습니다."를 표시한다. 팝업은 바깥 클릭·Esc·닫기 버튼으로 닫힌다.

### S-08 필터로 목록 좁히기
- 관련 ID: FR-07, BR-02, BR-08
- 사전 조건: 로그인 상태이며 카테고리·상태가 다양한 할일이 있다.
- 행동 흐름:
  1. 목록 뷰에서 카테고리 필터를 선택한다.
  2. 상태 필터(시작 전 / 진행중 / 완료 / 기한 초과) 중 하나를 선택한다.
- 기대 결과: 선택한 카테고리와 상태 조건을 모두 만족하는 본인 할일만 표시된다(AND). 상태는 KST 오늘 기준으로 판단한다.

### S-09 카테고리 생성·수정·삭제
- 관련 ID: FR-08, BR-01, BR-03, BR-10, BR-11
- 사전 조건: 로그인 상태.
- 행동 흐름:
  1. 카테고리 관리에서 새 카테고리 이름을 입력해 생성한다.
  2. 생성한 카테고리의 이름을 수정한다.
  3. 할일 등록·수정 시 해당 카테고리를 지정한다.
  4. 더 이상 필요 없는 카테고리를 삭제한다 (E-09 참조).
- 기대 결과: 본인 카테고리만 생성·수정·삭제된다. 카테고리는 사용자별로 관리된다. '기본' 카테고리는 수정·삭제할 수 없다 (BR-10). 카테고리 이름은 비어 있을 수 없고 사용자별로 유일하다 (BR-11).

## 5. 예외/경계 시나리오

### E-01 중복 이메일 가입
- 관련 ID: FR-01, BR-07
- 사전 조건: 동일 이메일로 이미 가입된 계정이 있다.
- 행동 흐름:
  1. 회원가입 화면에서 기존 이메일로 가입을 요청한다.
- 기대 결과: 가입되지 않고 오류가 안내된다. 이메일은 대소문자를 구분하지 않고 중복을 판단한다 (예: USER-A 이메일을 대문자로 바꿔 입력해도 중복).

### E-02 미인증 접근 및 토큰 만료
- 관련 ID: FR-01, BR-01
- 사전 조건: 로그인하지 않았거나, Refresh Token이 만료되었거나 유효하지 않다.
- 행동 흐름:
  1. 앱의 보호된 화면에 접근한다.
- 기대 결과: 접근이 거부되고 로그인 화면으로 이동한다. 로그인 실패 시 이메일·비밀번호를 구분하지 않고 "이메일 또는 비밀번호가 올바르지 않습니다."를 안내한다.

### E-03 종료일자가 시작일자보다 빠른 경우
- 관련 ID: FR-03, FR-04, BR-04
- 사전 조건: 할일 등록 또는 수정 화면.
- 행동 흐름:
  1. 시작일자보다 빠른 종료일자를 선택한다.
  2. 저장을 요청한다.
- 기대 결과: 저장되지 않고 오류가 안내된다. 시작일자 = 종료일자는 허용된다 (시작일자 ≤ 종료일자).

### E-04 카테고리 미지정 등록
- 관련 ID: FR-03, BR-03
- 사전 조건: 할일 등록 화면.
- 행동 흐름:
  1. 제목만 입력하고 카테고리를 지정하지 않은 채 저장한다.
- 기대 결과: 할일이 '기본' 카테고리로 저장된다.

### E-05 타인 할일 접근
- 관련 ID: FR-04, FR-05, FR-06, BR-02
- 사전 조건: 로그인 상태. 다른 사용자 소유의 할일이 존재한다.
- 행동 흐름:
  1. 타인 할일에 대한 조회·수정·삭제를 요청한다.
- 기대 결과: 요청이 거부되고 데이터는 변경되지 않는다. 목록·캘린더에는 본인 할일만 표시된다.

### E-06 할일 상태 경계
- 관련 ID: FR-06, FR-07, BR-08
- 사전 조건: 오늘 날짜(KST) 기준으로 아래 할일이 각각 존재한다. 상태는 저장하지 않고 판단한다(완료 → 기한 초과 → 시작 전 → 진행중 순).
- 행동 흐름 및 기대 결과:

| 할일 조건 | 기대 상태 |
|---|---|
| 시작일자 = 오늘, 미완료 | 진행중 |
| 종료일자 = 오늘, 미완료 | 진행중 |
| 종료일자 = 어제, 미완료 | 기한 초과 |
| 종료일자 = 어제, 완료 | 완료 |
| 시작일자 > 오늘, 미완료 | 시작 전 |

- 비고: 완료 처리한 할일은 체크 토글로 미완료로 되돌릴 수 있다 (BR-12).

### E-07 기한 초과 필터
- 관련 ID: FR-07, BR-08
- 사전 조건: 종료일자가 지난 미완료 할일과 종료일자가 지난 완료 할일이 있다.
- 행동 흐름:
  1. 상태 필터에서 '기한 초과'를 선택한다.
- 기대 결과: 종료일자가 지났지만 완료되지 않은 할일만 표시된다. 완료된 할일은 표시되지 않는다.

### E-08 필터 조합 경계
- 관련 ID: FR-07
- 사전 조건: 목록 뷰.
- 행동 흐름:
  1. 카테고리 필터와 상태 필터를 함께 선택한다.
  2. 상태 필터를 다른 값으로 바꾼다.
- 기대 결과: 카테고리 + 상태 1개가 AND로 적용된다. 상태 필터는 하나만 선택되며 새로 선택하면 기존 선택을 대체한다. 조건에 맞는 할일이 없으면 "조건에 맞는 할일이 없습니다."를 표시한다.

### E-09 카테고리 삭제 시 할일 이동
- 관련 ID: FR-08, BR-09, BR-03
- 사전 조건: 사용자 카테고리 A에 할일이 1건 이상 있다.
- 행동 흐름:
  1. 카테고리 A를 삭제한다.
  2. 목록 뷰에서 기존 A 소속 할일을 확인한다.
- 기대 결과: 카테고리 A가 삭제되고, 소속 할일은 삭제되지 않은 채 '기본' 카테고리로 변경된다.

### E-10 '기본' 카테고리 보호·카테고리 이름 검증·삭제 확인
- 관련 ID: FR-05, FR-08, BR-10, BR-11
- 사전 조건: 로그인 상태.
- 행동 흐름:
  1. '기본' 카테고리의 수정·삭제를 시도한다.
  2. 빈 이름 또는 이미 있는 이름으로 카테고리를 생성·수정한다.
  3. 할일 또는 카테고리를 삭제한다.
- 기대 결과: '기본' 수정·삭제 시도는 거부되고(400) 데이터는 변경되지 않으며 화면에는 수정·삭제 버튼이 표시되지 않는다 (BR-10). 빈 이름은 거부(400), 사용자별 이름 중복은 거부(409)된다 (BR-11). 할일·카테고리 삭제 전 확인창이 1회 표시되며 확인 시에만 삭제된다.
