## 1. 테스트 데이터

`backend/src/db/seed.js`는 `TRUNCATE`로 DB 전체를 비우므로 쓰지 않았습니다. 대신 [setup.mjs](setup.mjs)로 API를 호출해, 기존 데이터를 건드리지 않고 고유 계정과 공통 테스트 데이터(시나리오 §3)를 만들었습니다.

| 시나리오 ID | 실제 값 |
|---|---|
| USER-A | `e2e-a-1790905642211@example.com` / `password123` (카테고리 기본·업무·개인, TODO-A1~A6) |
| USER-B | `e2e-b-1790905642211@example.com` / `password123` (TODO-B1, id=20) |
| NEW | `e2e-new-1790905642211@example.com` (S-01에서 가입) |

다시 실행하려면 `node test/e2e/setup.mjs`를 실행합니다. 실행할 때마다 새 계정이 만들어집니다.

## 4. 발견된 결함

### BUG-01 모바일에서 캘린더 날짜 팝업이 화면 밖으로 넘침 (심각도: 낮음, 상태: 수정 완료)

- **재현:** 뷰포트 390×844에서 캘린더 탭의 날짜 셀을 클릭합니다.
- **기대:** 팝업 좌우에 16px 여백이 남고 화면 안에 들어옵니다 (스타일 가이드 §5.3).
- **실제(수정 전):** 팝업 폭이 401px로 뷰포트(390px)보다 넓어 오른쪽 테두리와 여백이 잘렸습니다.
- **원인:** `.calendar__day`의 `width: min(480px, calc(100% - 2 * var(--space-4)))`는 content-box 기준입니다. 프로젝트에 전역 `box-sizing: border-box`가 없어서 `padding: var(--space-6)`(좌우 48px)가 폭에 더해집니다.
- **수정:** `frontend/src/index.css`의 `.calendar__day`에 `box-sizing: border-box;`를 추가했습니다. 스타일 가이드 §6.8의 날짜 팝업 항목에도 반영했습니다.
- **재검증:** 390×844에서 팝업 폭 352px(left 19 / right 371)로 화면 안에 들어옵니다 (스크린샷 31을 수정 후 화면으로 교체). 1280px에서는 폭 480px 그대로입니다.

## 5. 참고 사항

- **콘솔 오류:** 기록된 오류는 모두 의도한 음성 테스트의 응답입니다 (401 로그인 실패·잘못된 토큰, 409 중복, 400 '기본' 보호·빈 이름, 404 타인 할일). 예상하지 못한 오류는 없었습니다.
- **테스트 방법상 주의:** 완료 체크박스는 서버 응답 뒤에 상태가 바뀌는 제어 컴포넌트라서, Playwright `check()`는 즉시 확인 단계에서 실패합니다. `click()` 후 PATCH 응답을 기다리는 방식으로 검증했습니다. 기능 결함이 아닙니다.
- **확인창 처리:** 삭제 확인창(`window.confirm`)은 Playwright MCP가 가로채므로 `browser_handle_dialog`로 취소와 확인을 각각 처리했습니다.
- **범위 외:** Access Token 15분 만료 후 자동 갱신은 시간 제약 때문에 직접 재현하지 않았습니다. 대신 잘못된 토큰으로 refresh가 실패했을 때 로그인 화면으로 가는 경로(E-02)를 확인했습니다.
- **남은 데이터:** E2E 계정 3개와 그 할일·카테고리가 DB에 남아 있습니다.
